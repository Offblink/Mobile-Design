缩放转场（zoom-transition）

容器变形（Container Transform）的整页版：点缩略图，新页从该元素的屏幕矩形放大到全屏；返回时整页缩回那个矩形再收场。Prism 里两处都用它——相机页点左下角相册方块进入相册、相册点任意照片进入看图页。起始态是非等比 scale（scaleX/scaleY 各自按矩形宽高算），整页精确填满源矩形、不裁不补；进场 280ms、退场 240ms，曲线 fast_out_slow_in。

组件要点

  • 源矩形：点谁就量谁——getBoundingClientRect() 相对屏幕算出 [x,y,w,h]（Prism 对应 Ui.rectOnScreen），进退场都复用同一份。
  • 起点变换：transform-origin:0 0 + translate(x,y) scale(w/W, h/H)。宽高分开算，所以起始态是压扁的——整页精确铺满那个 46px 方块 / 照片格，不裁边不留缝；结束前就恢复到 1:1，中途的形变正是「容器变形」的观感。
  • 旧页不卸载：Prism 在 Android 上要先 PixelCopy 截整帧当新 Activity 的窗口背景（否则源矩形之外露出黑底）；网页里旧页本来就压在下面，留着 .on 即可，效果等价且省掉一次截图。
  • 状态栏不缩放：单根挂在 .screen 上（Android 系统栏由 SystemUI 画，不进 Activity 的视图树）。进场时源页还盖着顶栏 → 走到终点才翻色；退场时新页顶边一动就露出下面那页 → 开场即翻。
  • 时长与曲线：进 280ms / 出 240ms（退场故意快 40ms），fast_out_slow_in = cubic-bezier(.4,0,.2,1)。
  • 两段守卫：转场期间 busy 拦掉所有点击；transitionend 之外再挂一个超时兜底（事件被更高优先级的样式改写吞掉时不卡死）。

动手点

  • 相机页点左下角相册方块 → 整页从那 46px 里长出来，状态栏全程只有 9:41 一根。
  • 相册里点任意一格 → 看图页从该格放大；页内照片会换成你点的那张。
  • 返回 → 整页缩回原格再消失，露出下面那页；连着走 相机 → 相册 → 看图 → 返回 → 返回 看层级回退对不对。
  • 动画中途快速连点：转场中不接新点击，页面不会卡在半路。

刻意没做

  • 不做淡入淡出替代缩放、不做等比 FIT（源比屏幕扁时会留黑边或裁切）、页面级转场不加 --spring 回弹（整页越过 100% 再回落读起来像故障——这是本库动效双轨的唯一例外）。
